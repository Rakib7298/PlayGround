Reader demo — The case for a hybrid browser

By the Panda Mobile team

Lightpanda is a headless browser written in Zig. It implements a DOM, JavaScript through V8, networking through libcurl, and both CDP and WebDriver BiDi servers. It is designed for automation, extraction and AI agents.

What it does not have is a graphical renderer. Its PNG and PDF output is a text-only rendering, with no compositor, no interactive scrolling and no CSS paint for the real mobile web. That makes a literal one-to-one Android clone a renderer project, not a port.

The hybrid alternative

Keep Chromium's WebView for pixels and touch, and use a Lightpanda-style engine for extraction and automation. This page exists so you can try the extraction path: open the menu and choose Reader mode. Navigation, advertisements, the sidebar and the footer should vanish, leaving the article.

A good reader mode is a small, honest example of what a headless engine can contribute to a mobile browser.

The extractor scores paragraph containers, picks the best subtree, removes boilerplate, whitelists readable tags and makes links and images absolute. It also removes duplicate headings and bylines.

For the native port, the app keeps a narrow JNI contract and a loopback CDP boundary. That keeps the engine replaceable and the UI stable while V8, Bionic and the Zig toolchain are brought up for Android.

./gradlew :app:assembleDebug
  • WebView renders and handles input.
  • The reader pipeline extracts the article.
  • A future native core handles automation.
